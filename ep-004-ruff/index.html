    01Briefing

    30 秒看懂

    先說背景
    寫 Python 的團隊通常會裝三四個工具：一個挑錯、一個整理檔案開頭的引用清單、一個統一排版，專案一大，每次存檔都要等好幾秒。
    它是什麼
    Ruff 是 Astral 公司用 Rust（一種跑起來接近機器速度的程式語言）寫的 linter（程式健檢工具）加 formatter（排版工具），一個工具取代上面那些。
    為什麼值得看
    快到感覺不到：整個 Django（很多網站在用的大型 Python 專案，約 16.6 萬行）檢查只要 0.06 秒，比老牌檢查工具 flake8 快 66 倍。
    要注意
    它不檢查型別（例如把字串傳進要數字的地方），那要另外搭配別的工具。
    最適合你的點子
    讓 AI 助手每次改完 Python 都先跑一次 Ruff，人工檢查時只看真正的改動。

    05Deep Dive

    想深入再展開

    實測紀錄每個指令、版本、三次的秒數，以及 Demo 跟命令列的比對

    2026-11-27（台灣時間）在雲端工作區實際執行（4 核 CPU、Python 3.11.18）。腳本與原始輸出在 lab/ 資料夾，clone 下來就能重跑。

    版本：ruff 0.17.6、flake8 7.5.0（pycodestyle 2.15.0、pyflakes 4.1.0）、black 26.10.1（編譯版）、pylint 4.1.4。對象：Django 主分支 f0e7bd9（2026-11-26），只算 django/ 底下 909 個 .py 檔、166,481 行。Ruff 一律不用快取、不讀專案設定，Black 每次用全新的快取資料夾、在全新的副本上真的改寫檔案。

    測試指令重點三次（秒）中位數
    整個 django/ruff check（E、F、W 三組）0.063、0.061、0.0650.063
    整個 django/flake8（預設規則）4.612、4.131、4.1604.160
    django/dbruff check（E、F、W 三組）0.031、0.027、0.0280.028
    django/dbruff check --select ALL（813 條穩定規則）0.085、0.084、0.0840.084
    django/dbflake8（預設規則）1.426、1.483、1.6451.483
    django/dbpylint（4 核並行，只跑 1 次；結束碼 30 代表有找到問題，不是失敗）32.83532.835
    整個 django/ruff format0.082、0.081、0.0800.081
    整個 django/black7.655、7.276、7.4827.482

    倍數用中位數算：4.160 ÷ 0.063 ≈ 66、32.835 ÷ 0.0843 ≈ 390、1.483 ÷ 0.0843 ≈ 18（0.0843 是未四捨五入的中位數 0.084287）、7.482 ÷ 0.081 ≈ 92。

    要注意的不公平之處：兩邊找到的問題數不一樣（flake8 輸出 4,394 行、Ruff 只有幾行），主因是 flake8 預設一行上限 79 字、Ruff 預設 88 字，而且 Ruff 的部分空白規則還在預覽版沒有預設啟用；所以這裡只比速度。Black 跟 Ruff 有差異的 41 個檔，範例是 shortcuts.py：Black 把一行 _("…") % queryset.model._meta.object_name 拆成兩行，Ruff 判斷塞得下、保留一行。

    Demo 跟命令列比對（lab/parity.py）：頁面用的是官方的 @astral-sh/ruff-wasm-web 0.17.6；「一鍵修好」是本集自己寫的（照位置從後往前套用、重疊的留到下一輪，最多 10 輪）。三個範例跟 ruff check --fix --unsafe-fixes 比：找到的問題、修好後的程式、剩下修不了的問題、ruff format 的結果，3 個範例 4 項全部一致。所以上面 Demo 的結果跟你在電腦上用命令列跑的一模一樣。

    五分鐘上手裝好、檢查、修好、排版，四行指令（本集實測過）
    在你的專案資料夾裡
    pip install ruff==0.17.6
ruff check .                  # 只挑錯
ruff check . --fix            # 安全的問題自動修
ruff format .                 # 排版（跟 Black 幾乎一樣）
    pyproject.toml：多開本集 Demo 那 7 組規則
    [tool.ruff]
line-length = 88

[tool.ruff.lint]
select = ["E", "F", "W", "I", "UP", "B", "SIM", "C4", "FAST"]

    不加 --unsafe-fixes 時，Ruff 只套用不會改變程式行為的修正；例如把 tags: list = [] 改成 None 再補判斷式，屬於「不安全」的修正，要自己確認。

    授權、限制與替代品MIT 可商用；不查型別；公司在 2026-03 宣布被 OpenAI 收購

    授權：MIT（以 repo 的 LICENSE 原文為準），可以免費商用、包進自己的 app。LICENSE 後半段列了 Ruff 改寫自哪些工具（autoflake、flake8 外掛等）以及它們的授權，散布時要把整份 LICENSE 一起附上（本集頁面附在 RUFF-LICENSE.txt）。

    公司：Ruff 背後的 Astral（也做 uv、ty）在 2026-03-19 宣布被 OpenAI 收購，雙方都說工具會維持開源；授權不變，但之後的方向可能更貼近 Codex 這類 AI 寫程式的產品。

    限制：① ruff rule --all 列出 977 條規則：815 條穩定、145 條預覽（要另外開 preview）、17 條已移除；--select ALL 實際啟用 813 條（815 條穩定規則中有 2 條互相衝突、被自動忽略；lab/select-all-settings.txt）。② 不檢查型別，要配 mypy、pyright 或 ty；「自動修好」有些會改變程式行為。③ 不支援外掛，pylint 或 flake8 自訂的檢查要等官方改寫。④ 本集 Demo 為了示範，把不安全的修正也全部套用了，自己專案請先用預設的安全模式。⑤ 頁面的 Demo 要下載約 10 MB 的 WebAssembly。

    工具做什麼跟 Ruff 比
    flake8挑錯，靠外掛擴充Ruff 內建它和多數熱門外掛的規則，快 66 倍（本集）
    pylint挑錯，規則最深能做跨檔推理，Ruff 改寫了其中 115 條（20 條還在預覽）；慢很多
    Black排版Ruff format 刻意模仿它，Django 上 95.5% 一字不差
    isort排 importRuff 的 I 規則取代
    mypy、pyright、ty檢查型別Ruff 不做，要搭配
    延伸探索與跨集組合同一家公司的 uv、前端版的 Biome、跟第 3 集的組合
    • uv：同一家公司做的 Python 套件管理，也是用 Rust 換速度（Apache-2.0／MIT）。
    • Biome：JavaScript／TypeScript 世界的 Ruff，挑錯加排版（Apache-2.0）。
    • Ruff 官方 Playground：所有設定都能調的線上版。
    • 跨集組合：第 3 集 Headroom 把工具吐給 AI 的 log 壓小；Ruff 則讓 AI 寫出來的程式先被自動訂正。兩個一起，等於 AI 寫程式時「讀進去的字少一點、交出來的程式乾淨一點」。
