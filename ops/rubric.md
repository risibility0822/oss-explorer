# 審查標準

審查員（`.claude/agents/oss-reviewer.md`）每項給 1–5 分。任何一項低於門檻，判定就是 `revise`。

| 項目 | 門檻 | 5 分的樣子 | 3 分的樣子 | 1 分的樣子 |
|---|---|---|---|---|
| **正確性** | 5 | 每個數字、授權、版本、使用者名單都查得到出處且吻合；頁面數字與 lab 輸出一致 | 有一兩處無法驗證但措辭保守 | 有錯的事實或對不上 lab 的數字 |
| **Demo 真實可玩** | 4 | 真的函式庫在瀏覽器裡跑，可以操作出有意義的結果；或真實執行結果配互動瀏覽；lab 腳本能重跑 | 只有靜態的執行紀錄，但是真的 | 示意或捏造、lab 空的或對不上 |
| **深度與洞見** | 3 | 講清楚原理（圖能幫助理解）、跟替代品的差異、什麼時候不該用 | 介紹完整但偏表面 | 像 README 摘要 |
| **對主人的價值** | 3 | 點子具體、可執行，有真實的商業模式或案例，至少一個貼近主人背景；跨集組合有意義 | 點子合理但泛用 | 空泛、跟主人無關 |
| **設計與完成度** | 3 | 第一屏就看到 Demo；手機、深色乾淨；字級與對比好；視覺從主題取材 | 整齊但普通 | 破版、看不清楚、像模板 |
| **原創與有趣** | 3 | 選題或 Demo 讓人想點開、想玩；有意外的發現 | 正常 | 無聊或跟以前某集太像 |

## 校準範例：舊版第 001 集（Yjs，已被 rembg 版取代，原頁在 git 歷史 commit 60467da）

- **正確性 5**：星數、授權、commit 統計有出處和日期；benchmark 與 lab/bench.json 一致；第三方網站把 y-crdt 授權標錯，有回去看 LICENSE 原文更正。
- **Demo 5**：三台模擬裝置跑真的 Yjs，可以斷線、各自編輯、重連合併；另有 benchmark、JS↔Python 互通、Hocuspocus 實測，lab 都能重跑。
- **深度 4**：原理圖把「字元身分證、左鄰、狀態向量」講清楚，也有替代品比較；GC 與歷史的取捨可以再深入一點。
- **價值 4**：五個點子具體，其中兩個貼近主人背景；商業面有舉 Tiptap 的實例。
- **設計 4**：第一屏就是 Demo，三種人用三種顏色，手機與深色都乾淨；原理圖在手機上偏小。
- **原創 3**：Yjs 是常見題材，但 Demo 有趣。

審查員要比這個範例更嚴格，不要更寬鬆。
