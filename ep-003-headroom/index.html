01Briefing

30 秒看懂

先說背景
AI 助手（Agent，會自己去查資料、跑指令的 AI）每查一次，工具就吐回一大包 log（程式邊跑邊寫下的流水帳）給模型讀；模型是讀文字、回答問題的 AI 本體，讀越多字越貴、越慢。
它是什麼
Headroom 是一段能裝進你程式的 Python 工具，在送給模型前壓縮：刪掉每筆都重複的欄位名（像 level、service 這種標籤）；Apache-2.0，可免費商用。
為什麼值得看
300 筆 log 少讀 41%，只用 CPU（不用顯示卡，一般筆電就能跑）讀完從 231 秒變 96 秒，找出錯的那行一樣答對。
要注意
資料沒丟，但查單筆數字時小模型原樣答對 2/5、壓縮後 0/5；查細節前先用自己的資料測。
最適合你的點子
替 FastAPI 服務加一層「省 token 帳單」，先量自己的流量能省多少。

04Ideas

你可以拿它做什麼

FastAPI 服務的「省 token 帳單」一個週末

在 FastAPI 服務前面接一層 Headroom，再加一頁「這個月省多少錢」的報表，賣給台灣接 AI 的中小團隊。

Mac 上的「建置失敗翻譯機」一個月

Xcode 或 npm 建置失敗時，篩出錯誤段落交給本機小模型，用中文說哪裡壞了；建置 log Headroom 不壓，篩選要自己做。

給小模型的「格式選擇器」一個週末

同一份資料試三種寫法，用你的模型考幾題，自動挑答對多又省字的。

客服後台的訂單紀錄瘦身一個月

客服問 AI 某位客人的訂單時，紀錄常上百筆；先壓再問，回得快、帳單小。

五分鐘上手本集實跑過的最小程式：一個函式壓縮整串對話

pip install headroom-ai==0.45.0（要 Python 3.11 以上）。不需要 API 金鑰，也不用下載模型。

lab/scripts/minimal.py
import os, sys
os.environ["HEADROOM_OFFLINE"] = "1"          # 不連網、也關掉預設開啟的匿名統計
from headroom import compress

tool_output = open(sys.argv[1]).read()        # 工具吐回來的 JSON（這裡用 300 筆 log）
messages = [
    {"role": "user", "content": "哪個服務出錯？"},
    {"role": "assistant", "content": None, "tool_calls": [
        {"id": "c1", "type": "function", "function": {"name": "query_logs", "arguments": "{}"}}]},
    {"role": "tool", "tool_call_id": "c1", "content": tool_output},
]
result = compress(messages, model="gpt-4o")
print(result.tokens_before, "→", result.tokens_after, result.transforms_applied)
print(result.messages[-1]["content"][:160])
# 接著把 result.messages 照常送給任何相容 OpenAI 格式的模型（本集用 llama.cpp 跑 Qwen2.5-1.5B）

授權、限制與替代品Apache-2.0 可商用；預設開啟匿名統計；小模型讀表格要先測

授權：程式是 Apache-2.0（repo 的 LICENSE 原文），商用、修改、閉源都可以，要保留 NOTICE。處理一般文字用的 Kompress-v2-base 模型在 Hugging Face 標示 Apache-2.0；本集只用到 JSON 表格化，沒有下載這個模型。小模型 Qwen2.5-1.5B-Instruct 也是 Apache-2.0。

商業模式：開源核心＋企業版。README 寫「Headroom OSS 是為了展示一台筆電上能做到什麼，所以省得比它能省的少」，更大的節省放在付費的 Headroom Enterprise。開源版本身沒有功能鎖。

統計：匿名統計預設開啟（壓縮比、模型名稱、作業系統，官方說不送內容），用 HEADROOM_OFFLINE=1、HEADROOM_TELEMETRY=off 或 DO_NOT_TRACK=1 關掉。做產品給客戶用時一定要關。

成熟度：2026-01-07 第一個 commit，到 2026-11-25 共 3,826 個 commit、436 個不同作者 email，版本 0.45.0（還沒到 1.0），改版很快。

坑：純文字的建置 log 沒被壓（0%）；壓成表格後資料一筆不少，但小模型查細節會看錯欄；log 太長（本集 2,000 筆）壓完仍超過小模型的上限，要先自己篩。

做法怎麼省在哪跑授權
Headroom依內容種類挑壓法：JSON 變表格、程式碼看語法、文字用小模型刪字；原文可要回來本機（函式、代理伺服器、MCP）Apache-2.0
TOON（toon-format/toon）只是一種格式：同樣形狀的清單寫成表頭＋每行的值，跟這集看到的表格很像你自己轉MIT
LLMLingua（微軟）用小模型判斷哪些字可以刪，偏向長篇文字本機，要下載模型MIT
自己先篩只把 ERROR、相關的那幾筆送出去你的程式—
延伸探索與跨集組合本集的另一半 llama.cpp、TOON，以及跟前兩集怎麼接
  • llama.cpp：本集讓小模型在 CPU 上跑的引擎（MIT）。它讀越長的內容每個 token 越慢（本集 log：100 筆壓縮後每秒 212 個、300 筆原樣只剩 86 個），所以省下的時間比省下的字還多。
  • TOON：想自己把 JSON 轉成表格，不想整包裝 Headroom，可以只用這個格式。
  • LLMLingua：壓縮長篇文字（文件、對話）的另一條路。
  • 跨集組合：第 001 集 rembg 證明 AI 可以整個搬到使用者的機器上跑；這集補上下一步：本機小模型要讀得快，送進去的字就要先瘦身。第 002 集 handwired 是規則寫死、一題都不會錯的網路，正好對照這集小模型「查細節會看錯」。
