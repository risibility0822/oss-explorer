Yjs：幫任何 App 加上 Google Docs 式的多人協作

Yjs 是一套 CRDT 函式庫：好幾台裝置（就算離線）同時改同一份資料，重新連線後會自動合併，不用伺服器當裁判，也不會互相覆蓋。下面這三台「裝置」跑的是真的 Yjs 13.6.33。

主鏡頭：厲害巨星級單品CRDTlocal-first即時協作
三台內容一致 ✓

任何一台都可以直接打字、勾選待辦、按「斷線」。試試看：讓兩台斷線、各自改同一行，再接回來。

網路是在頁面裡模擬的：每次修改產生一個 Yjs update（二進位），隔「網路延遲」後交給其他在線裝置；斷線的裝置重連時，用狀態向量（state vector）只交換彼此缺少的部分。合併邏輯完全是 Yjs 本身。中文輸入法選字期間不會送出半成品。

為什麼值得認識怎麼運作實際執行紀錄五分鐘上手拿它做什麼跨集組合限制與比較延伸探索來源

為什麼值得認識

厲害在哪

協作功能出了名的難做，Jupyter 團隊花了好幾年，最後選了 Yjs。官方文件說它每週下載量超過 100 萬次，README 列出的使用者包括 Linear、Evernote、GitBook、JupyterLab、Proton Docs、AFFiNE、AWS SageMaker。我實測依序打 10,000 個中文字，文件只有 30,016 bytes，純文字本身是 30,000 bytes：附帶的協作資訊幾乎不佔空間。

好玩在哪

它完全不管網路怎麼傳：WebSocket、WebRTC 點對點、Matrix、甚至一個檔案傳來傳去都行，資料到了就能合併，順序不重要。同一份文件也能被 Rust（yrs）、Python（pycrdt）、Swift（yswift）讀寫。我讓 JavaScript 寫的文件給 Python 改，再交回 JavaScript，內容完整無誤（見下方紀錄）。

商業潛力在哪

Yjs 本身是 MIT，免費商用。錢在它周邊：Tiptap 把自家 MIT 授權的 Hocuspocus 伺服器包成託管服務 Tiptap Collab 收費；README 的 provider 清單裡也有 Liveblocks、y-sweet、PartyKit 等託管方案。換句話說，「讓別人的 App 也能多人協作」本身就是一門生意，而在自己的 App 裡加上協作，就是一個能收費的差異化功能。

它怎麼運作：每個字都有身分證

① 編號而不是位置。每個字都記著「誰（client）的第幾筆（clock）」。刪掉的字留下墓碑，不會真的消失，所以別人引用到它也不會亂掉。

② 插入時記住左邊的鄰居。新字記得「我原本插在誰右邊」。兩個人同時插在同一處，這就是衝突。

③ 交換缺少的部分，用固定規則排序。狀態向量就是「我每個人各收到第幾筆」。同步時只送對方缺的；碰到同一位置的衝突，大家用同一套規則（依 client 編號等）決定先後，所以不管更新到達的順序如何，算出來都一樣。

五分鐘上手

最小組合：前端用 yjs 加上 Hocuspocus 的 provider，後端跑 Hocuspocus。下面兩段就是 D 項實測的程式碼（精簡版）。

server.mjs（npm i @hocuspocus/server）
import { Server } from '@hocuspocus/server'

const server = new Server({ port: 1234 })
await server.listen()   // 預設存在記憶體；正式環境加 @hocuspocus/extension-database 等擴充
client.js（npm i yjs @hocuspocus/provider）
import * as Y from 'yjs'
import { HocuspocusProvider } from '@hocuspocus/provider'

const doc = new Y.Doc()
new HocuspocusProvider({ url: 'ws://localhost:1234', name: 'my-room', document: doc })

const todos = doc.getArray('todos')          // 共享陣列
todos.observe(() => render(todos.toJSON()))  // 任何人改了都會觸發
todos.push([{ t: '買牛奶', done: false }])     // 本機改動 → 自動同步給所有人

要離線也能用，再加 y-indexeddb 把文件存在瀏覽器；要接 ProseMirror、Tiptap、CodeMirror、Monaco、Lexical 等編輯器，各有現成的綁定。

選單列上一個小清單（購物、待辦、出國清單），全家的 Mac 和手機一起改，離線也能改。原生 UI 外殼加上 WebView 裡跑 Yjs（Swift 原生綁定 yswift 更新較慢），同步用自架的 Hocuspocus。

工作量：一個月　·　價值：開源核心＋付費託管或企業授權，鎖定台灣的接案與 SaaS 團隊

丟一個連結到 LINE 群組，不用註冊就能一起排行程、分帳、投票，每個人的游標顏色都不同。資料用 Yjs，房間用 Hocuspocus 或 y-sweet。

工作量：一個週末做出原型　·　價值：台灣市場的病毒式傳播工具；靠進階版（匯出、範本、無限房間）收費

限制與比較

  • v14 正在換版。npm 的 latest 還是 13.6.33，14.0.0 放在 next/beta tag，GitHub 上已到 v14.0.0-rc.30，也開始以新名稱 @y/y 發布。新專案建議先用 13.x，並留意升級說明。
  • 權限不歸 Yjs 管。誰能讀、誰能寫，要在 provider 或伺服器那一層處理（例如 Hocuspocus 的驗證 hook）。Yjs 只負責合併。
  • 文件只會變大。刪除會留下墓碑。預設開啟的 GC 會清掉被刪內容，但開著 GC 就不保留完整歷史；要做「回到舊版本」得關掉 GC，或自己存快照。
  • 自己綁輸入框沒那麼簡單。要處理游標位置與中文輸入法（本頁 Demo 示範了選字期間先不送出的做法）。富文本請直接用現成的編輯器綁定。
  • Apple 原生生態較弱。yswift 最新版本是 0.2.1，2024 年後少有更新。Mac/iOS 原生 app 可考慮 WebView，或評估 automerge-swift。

延伸探索

  • Hocuspocus：MIT 授權的 Yjs WebSocket 後端，v4 起不只支援 Node.js 執行環境。
  • y-crdt（yrs）：Yjs 的 Rust 移植版，是 Python、Swift 等綁定的基礎。
  • pycrdt：Python 綁定，JupyterLab 的協作後端就用它。
  • Loro與Automerge：另外兩個主流 CRDT 函式庫，值得各自專門介紹一集。
  • crdt-benchmarks：Yjs 作者維護的效能比較。
